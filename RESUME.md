# AlertLens — Resume Bullets

- Built a SOC alert-triage dashboard (FastAPI + PostgreSQL + React) that deduplicates and correlates alerts into incidents, cutting 152 seeded alerts to 8 incidents with a 94.74% dedup/correlation reduction and an auditable, reopenable suppression queue.
- Calibrated a false-negative budget (0.95 recall target) on held-out incidents: the 5-seed synthetic evaluation scored recall 0.9419 ± 0.0699 and precision 0.6451, missing the target in seeds 2 and 3.
- Evaluated the same model on real UNSW-NB15 test flows (35,069 flows, seed 42): recall 0.9486 (95% Wilson [0.9458, 0.9514]), precision 0.9334, with the 0.95 target not met — measured in the work-copy run.
- Made the ML scoring honest: the model uses only six real flow features, alerts with no flow evidence are never scored and never suppressed, and the evidence package says so, with 89 backend tests passing at 96% coverage.

## NOTES (not for a resume — caveats and how the numbers were measured)

- All numbers are measured, not estimated: `python benchmark.py` in the extracted portable build (Part A demo pipeline, Part B 5-seed synthetic scenario set; Part C NOT RUN there, no dataset file shipped). Part A: 152 alerts → 8 incidents (8 surfaced, 0 suppressed), headline 94.74%, recall 1.0, precision 0.5 — the demo set is synthetic, so Part A is a pipeline check, not production performance. A work copy with a UNSW-trained model scores the same demo set differently (6 surfaced, 2 suppressed, headline "target not met", recall 0.75); see RESULTS.md.
- Part C was re-run in the work copy with the 6-feature severity-free model and is labelled "measured in the work-copy run". The dataset file (`data/unsw-nb15.csv`) is not in the distributed zip, so Part C is NOT RUN from an extracted copy. The portable build ships no trained model: it trains a synthetic model in memory and calibrates its own threshold (seed 42); it never reuses the UNSW model's threshold.
- The 0.95 recall target was NOT met on Part B (seeds 2 and 3) or Part C; mean pooling ties AlertLens on recall (0.9419) and beats it on precision (0.7256), so no pooling advantage is claimed. Part B is an upper bound: the generator and the model share the same flow distributions.
- Docker and nginx are configured (Dockerfile, compose, nginx reverse proxy with server-side API-key injection) but have NOT been run in this environment — there is no Docker CLI in the VM, so no `docker compose` or `docker_smoke.py` output exists. To verify on a machine with Docker: `cp .env.example .env` (set a real API_KEY), `docker compose up --build -d --wait`, `python scripts/docker_smoke.py`, `docker compose down -v`.
- Backend: 89 pytest passed, 1 skipped, 96% coverage. Frontend: 17 Vitest passed, `npm run build` passes. Screenshots in `docs/screenshots/` were re-captured against the portable build (8 surfaced, 0 suppressed, headline 94.74%, recall 1.0).
- Research basis: Devo 2025, Sophos/NorthSec 2026, Koumourou et al. 2025 (CRITIS 2025). The "under one third use AI for triage" claim in the README is brief-only and was not independently verified.
